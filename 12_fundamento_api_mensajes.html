La API: mensajes sin memoria

Cómo se habla con Claude desde Python: una lista de mensajes con roles, que hay que reenviar completa en cada llamada. Y lo que eso cuesta a medida que la conversación crece.

1. Una llamada

12_agent_with_llm.py · líneas 191–207 (modo real)
import anthropic
cliente = anthropic.Anthropic()            # lee ANTHROPIC_API_KEY del entorno

respuesta = cliente.beta.messages.create(
    model="claude-opus-5-5",               # qué modelo
    max_tokens=16000,                      # tope de la respuesta
    system=SISTEMA,                        # instrucciones generales
    tools=HERRAMIENTAS,                    # lo que puede pedir
    messages=mensajes,                     # toda la conversación
    ...
)

Cada llamada envía todo lo que el modelo necesita y recibe una respuesta. El parámetro central es messages.

2. Los mensajes y sus roles

mensajes = [
    {"role": "user", "content": "Limpia toda la cuadricula."},
    {"role": "assistant", "content": [ ...pedido de herramienta... ]},
    {"role": "user", "content": [ ...resultado de la herramienta... ]},
    {"role": "assistant", "content": [ ...otro pedido... ]},
    ...
]
  • user: lo que llega al modelo (la tarea, y después los resultados de las herramientas).
  • assistant: lo que respondió el modelo.
  • system (aparte, no en la lista): instrucciones que valen para toda la conversación. Se ve en el fundamento del prompt de sistema.

content puede ser un texto o una lista de bloques: texto, pedido de herramienta (tool_use), resultado de herramienta (tool_result), y en los modelos actuales también bloques de razonamiento (thinking).

3. Sin memoria

La API no recuerda nada entre llamadas. Cada vez hay que reenviar la conversación entera. La “memoria” del agente es la lista mensajes, que vive en tu programa.
12_agent_with_llm.py · líneas 160–162 y 183
respuesta = decidir(mensajes)
...
mensajes.append({"role": "assistant", "content": respuesta.content})   # lo que dijo
...
mensajes.append({"role": "user", "content": resultados})               # lo que pasó

Fíjate que se agrega respuesta.content completo, no solo el texto: si la respuesta trae bloques de razonamiento o pedidos de herramienta, tienen que volver tal cual en la próxima llamada.

Es parecido al estado interno del agente deliberativo de la 2.1 (el set de visitadas), con una diferencia: aquí el estado es texto, y se le entrega completo al modelo en cada decisión.

4. Lo que cuesta

Midiendo el tamaño de lo que se envía en cada llamada en la corrida del script (sistema + herramientas + mensajes):

Caracteres
Sistema + descripción de herramientas (fijo)1 133
Primera llamada1 159
Última llamada (19.ª)4 760
Total enviado en las 19 llamadas57 147 (≈ 14 000 tokens)

Estimación con la regla aproximada de 4 caracteres por token. En modo real se suman la respuesta y el razonamiento de cada llamada.

Cada llamada reenvía todo lo anterior, así que el total crece más o menos con el cuadrado de la cantidad de pasos. Con tareas largas eso se vuelve caro y lento. Hay técnicas para mitigarlo (cachear el principio fijo de la conversación, resumir el historial), pero el punto de fondo queda: cada decisión de un agente con LLM es una llamada a un modelo grande, con costo y demora reales.
