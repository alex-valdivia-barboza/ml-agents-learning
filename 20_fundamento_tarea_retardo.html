Entrenar el bloque: copiar con retardo

La Parte 7 arma un modelo completo (embeddings, un bloque, salida) y lo entrena con Adam en una tarea que exige saber dónde está cada dígito. En 100 pasos llega al 100 %, y sus cuatro cabezas aprenden a mirar exactamente 3 posiciones atrás.

1. La tarea

20_transformer_bloque.py · líneas 149–156
V, T, RETARDO = 10, 16, 3
D, H, N_BLOQUES, PASOS = 32, 4, 1, 600

def lote(n):
    x = rng.integers(0, V, (n, T))
    return x, x[:, :T - RETARDO]

Cada ejemplo son 16 dígitos al azar. El objetivo en la posición t es el dígito de la posición t − 3, así que x[:, :13] son las respuestas de las posiciones 3 a 15. Es la tarea más simple que necesita las tres piezas nuevas: auto-atención (traer información de otra posición), máscara causal (la respuesta está atrás, nunca adelante) y posiciones (“3 atrás” es una distancia, no un contenido). Como los dígitos son al azar, mirar solo el contenido no sirve de nada.

2. El modelo completo

mini_transformer.py · líneas 112–121
def forward(modelo, tokens, guardar=None, **opciones):
    B, T = tokens.shape
    x = modelo["E"][tokens]                        # tokens → vectores
    if modelo["posiciones"]:
        x = x + modelo["P"][np.arange(T)]          # + dónde está cada uno
    for p in modelo["bloques"]:
        x = bloque(x, p, modelo["H"], guardar=guardar, **opciones)
    x = layer_norm(x, modelo["lnf_g"], modelo["lnf_b"])
    return x @ modelo["W_salida"]                  # (B, T, V): puntajes del siguiente token

Esta es, literalmente, la arquitectura de GPT: embeddings + posiciones → N bloques → normalización final → una matriz que convierte cada vector en V puntajes (logits). La 4.3 usa esta misma función con más bloques y con caracteres del Quijote. **opciones recoge argumentos con nombre extra (como residual=False) y los pasa tal cual a bloque; sirve para los experimentos.

3. El entrenamiento, y Adam

20_transformer_bloque.py · líneas 161–170
optimizador = Adam(params, tasa=3e-3)
...
    logits = mt.forward(modelo, x)                 # (32, 16, 10)
    L = cross_entropy(logits[:, RETARDO:], y)      # solo las posiciones con respuesta
    L.backward()
    optimizador.paso()

logits[:, RETARDO:] descarta las 3 primeras posiciones, que no tienen respuesta. El recorte es una operación de autograd más (__getitem__): el gradiente de esas posiciones queda en cero.

Adam (mini_autograd.py, líneas 235–254) mejora el Adagrad de la 3.5 en dos cosas:

  • En vez de sumar todos los gradientes al cuadrado desde el inicio (lo que hace que la tasa de Adagrad solo pueda bajar), usa un promedio móvil (v): recuerda sobre todo los últimos ~1 000 pasos.
  • Suaviza también el gradiente mismo (m, promedio de los últimos ~10): si los pasos apuntan siempre al mismo lado, se acumula “inercia”; si oscilan, se cancelan.
  • Las líneas m_hat y v_hat corrigen el arranque: m y v empiezan en cero y sin la corrección los primeros pasos serían demasiado chicos.

Con un bloque transformer, el descenso de gradiente simple con una sola tasa funciona mal: los distintos parámetros (embeddings, Wq, normas…) tienen gradientes de escalas muy distintas. Adam es el optimizador con el que se entrenan prácticamente todos los transformers.
